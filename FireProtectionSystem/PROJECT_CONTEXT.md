# FireProtectionSystem — Project Context

> Source of truth: the C#/XAML source in this repository. Where documentation and code disagree,
> the code wins. "Snowdon" is **not** a software integration in this project — it is only a sample
> architectural model name used in test data (see `extractTest.json` and `TextFile1.txt`).

## 1. Project Overview

A Revit add-in for fire-protection system planning. The current codebase implements two major
capabilities: (a) **model-data extraction** from the host MEP model and linked architectural models
into a normalized JSON snapshot, and (b) **sprinkler placement calculation + actual Revit
FamilyInstance placement** (the "BruteForce" workflow).

## 2. Project Purpose

Read the active Revit model (and linked architectural models), extract fire-protection-relevant
data (levels, rooms with boundaries, ceilings, obstacles, existing sprinklers), normalize it to a
deterministic host-MEP-coordinate JSON, then calculate and place sprinklers. TextFile1.txt describes
the original Phase 1 charter as "production-ready model-data extraction" with placement as a later phase;
the placement phase is now implemented in code (see [[PROGRESS]]).

## 3. Technology Stack

- C# / .NET, WPF for the UI.
- Revit API (RevitAPI.dll, RevitAPIUI.dll) — version-specific per build configuration.
- Newtonsoft.Json 13.0.4 for serialization.
- Two production projects + one test runner:
  - `FireProtection.Backend` (extraction, calculation, placement, Revit entry points)
  - `FireProtection.UI` (WPF front-end, ViewModels, result models, service interfaces)
  - `FireProtection.Tests` (console Exe running a Revit-free calculation test harness)

## 4. Target Environment

- Revit 2024 → `net48` (x64)
- Revit 2025 / 2026 → `net8.0-windows` (x64)
- Build configurations: `Debug`, `Release`, `Revit2024`, `Revit2025`, `Revit2026`.
- Revit API referenced via `HintPath` to `C:\Program Files\Autodesk\Revit <ver>\`; `Private=False`
  (Revit supplies the DLL at runtime).
- `ImplicitUsings` is **disabled** everywhere; `LangVersion` is `7.3`.

## 6. Backend Overview

Owns all Revit-API-aware logic: extraction, calculation, and placement. It references the UI project
(see [[ARCHITECTURE]] dependency direction). Key responsibilities:

- **Extraction** (`Services/Model/*`, `Services/Extraction/*`): read-only, zero-transaction.
- **Calculation** (`Services/Placement/Sprinklers/Final/BruteForce/*`): pure, Revit-free engine.
- **Placement** (`Services/Placement/Sprinklers/Final/RevitSprinklerPlacementService.cs`): creates
  Revit `FamilyInstance` elements.
- **Revit entry points** (`Revit/FireProtectionApplication.cs`, `Commands/FireProtectionCommand.cs`).

## 7. UI Overview

WPF MVVM front-end. It does **not** reference `FireProtection.Backend`. It defines the service
interfaces (`ISprinklerPlacementService`, `ISprinklerFamilySource`, `IPlacementInputExporter`) and the
calculation **result models** (`CalculatedSprinklerPoint`, `RoomCalculationResult`,
`BruteForceCalculationResult`, `SprinklerPlacementResult`). Concrete Backend services are constructed
in `FireProtectionCommand` and injected through the `UiLauncher` → `MainWindow` → `MainWindowViewModel`
→ `SprinklerBruteForceViewModel` constructor chain.

## 8. Revit Integration

- `FireProtectionApplication : IExternalApplication` builds the ribbon ("Fire Protection" tab/panel/
  button) on startup. The `.addin` manifest registers **only** the Application add-in (generated by
  the `DeployToRevit` build target).
- The ribbon button's `PushButtonData` targets `FireProtection.Backend.Commands.FireProtectionCommand`
  (an `IExternalCommand`), so the command is launched from the ribbon, not a separate `<Command>` entry.
- `FireProtectionCommand` runs extraction, builds the supporting services, and opens the modal UI.

## 9. Extraction System

Pipeline (all host-MEP normalized, feet):

- `LevelExtractor` — levels from host + links, with elevations.
- `RoomExtractor` — rooms with outer/inner loops, curved boundaries, hazard classification
  (`HazardClassifier.ClassifyByName`), ceiling association, existing-sprinkler association.
- `CeilingExtractor` — 3D solid inspection; slope/type classification (`FLAT`, `SLOPED`, `STEPPED`,
  `NONE`); bottom/top elevations.
- `ObstacleExtractor` — columns, beams, walls, MEP curves relevant to placement.
- `ExistingSprinklerExtractor` — family/type, mount, location of existing sprinklers.
- `FireProtectionExtractionService` orchestrates the above, validates (`ModelExtractionValidator`),
  and exports (`JsonSnapshotExporter`) a `ModelSnapshot`.

## 10. Sprinkler Placement System

The "BruteForce" workflow:

1. UI builds `PlacementRoomSelection` items from selected rooms.
2. `PlacementInputBuilder.Build` → `PlacementInputSnapshot` (in-memory; never reads a JSON file).
3. `BruteForceCalculationService.Calculate` → `CalculatedSprinklerPoint` list (X/Y/Z, room/level ids).
4. `RevitSprinklerPlacementService.PlaceSprinklers` creates Revit `FamilyInstance` elements.

See [[SPRINKLER_POINT_CALCULATION_EXPLAINED]] for the exact X/Y/Z algorithm.

## 11. Hazard Classification

`HazardClassifier.ClassifyByName(roomName)` produces a `HazardResult` (e.g., `Light`, `OH1`, `OH2`,
`EH1`, `EH2`). This classification is **tagging only** in the current code — the provisional placement
rules use the **same 15 ft placeholder for every hazard class** (`DefaultHazardPlacementRules`);
`HasApprovedRules == false`. NFPA13-2022 approved, hazard-specific spacing is **not** implemented.

## 14. Important Domain Concepts

- **Host-MEP coordinate system**: all extracted geometry is expressed in the host model's coordinate
  space (feet). Linked-model geometry is transformed during extraction.
- **PlacementInputSnapshot**: the in-memory contract the Revit-free calculation engine consumes.
- **ModelSnapshot**: the serialized extraction output (JSON), consumed by the UI via deserialization
  into `FireProtectionUiData`.
- **Provisional spacing**: 15 ft `MaxSpacingFt`, 7.5 ft `CoverageRadiusFt`, 1 ft clearances — placeholder.
- **ReviewRequired**: rooms are flagged (e.g., missing/sloped ceiling, provisional rules) and must be
  reviewed by an engineer.

## 15. Important Constraints

- Backend → UI dependency only; UI must never reference Backend.
- Linked geometry is normalized at extraction time; placement applies **no** second transform.
- Extraction is read-only and uses **no** transaction (model is never dirtied).
- Placement is gated behind `[Transaction(TransactionMode.Manual)]` on the command; the placement
  service opens its own transaction when creating elements.
- Revit API is referenced via absolute `HintPath`; build only succeeds where those DLLs exist.

## 16. Known Limitations

- Provisional 15 ft spacing is **not** NFPA13-2022 compliant.
- Sloped / unsupported ceilings fall back to `LevelElevationFt + CeilingHeightFt` and are flagged.
- Linked ceilings may not be found by `FindCeilingHost` (host-document only); falls back to level-based
  placement.
- Obstacles are axis-aligned bounding boxes + 1 ft clearance; curved/diagonal obstacles are approximated.
- Collision, Smoke Detector, and Notification Appliance tabs are placeholders (no logic).
- Runtime Revit placement has **not** been verified in this environment (no live Revit host).
